# Design: A0 data and cloud foundations

Evidence was gathered on 2026-11-16. Items marked **[verify]** were not confirmed from a primary source; each has a spike or P1 check that confirms it.

## Decisions and evidence

| # | Decision | Alternatives rejected | Evidence | Cost to change |
|---|---|---|---|---|
| 1 | **PostgreSQL 18**, with the same major version locally (compose `postgres:18`), on RDS and Aurora, and for self-hosters. | PG 17: no built-in UUIDv7. | PG 18 GA 2025-09-25; community EOL 2030-11-14; current minor 18.7 (https://www.postgresql.org/support/versioning/). RDS: PG 18 since 2025-11-14, latest 18.6, standard support to 2031-02-28 (https://docs.aws.amazon.com/AmazonRDS/latest/PostgreSQLReleaseNotes/postgresql-release-calendar.html). Aurora PG 18 GA 2026-06-11 (https://aws.amazon.com/about-aws/whats-new/2026/06/amazon-aurora-postgresql-major-version-18). **Spike 2.1 (2026-11-17): pass.** Compose pins `postgres:18.7`; `just psql -c 'select uuidv7()'` returns a v7 UUID on PostgreSQL 18.7. | High |
| 2 | **Vanilla Postgres features only.** The only extension allowed is `pgcrypto`, and only if a spike needs it. **No pgmq.** Jobs use a `FOR UPDATE SKIP LOCKED` table (later `apalis`, which uses the same method). | pgmq; pg_cron for app logic. | pgmq is not in the RDS PG 17/18 extension list (https://docs.aws.amazon.com/AmazonRDS/latest/PostgreSQLReleaseNotes/postgresql-extensions.html). Self-hosters run plain Postgres. | High |
| 3 | **Aurora DSQL is rejected.** | DSQL | It has no triggers and no extensions. Isolation is fixed at Repeatable Read with optimistic retries, and transactions are capped at 3,000 rows. SKIP LOCKED and LISTEN/NOTIFY are not listed. **Correction to the earlier chat claim: DSQL now supports foreign keys** (announced 2026-08-27). Sources: https://docs.aws.amazon.com/aurora-dsql/latest/userguide/CHAP_quotas.html, https://aws.amazon.com/about-aws/whats-new/2026/08/aurora-dsql-foreign-key-constraints/ | n/a |
| 4 | **Multi-tenancy uses shared tables with `org_id` on every tenant row and Postgres RLS** (`FORCE ROW LEVEL SECURITY`). The app connects as a role that is neither table owner nor `BYPASSRLS`. Migrations run as a separate owner role. Enterprise customers can get a dedicated database with the same schema. | Schema per tenant; database per tenant by default. | AWS RLS multi-tenant guidance: owners and `BYPASSRLS` skip policies unless FORCE is set, and a shared login with a session variable scales better than a role per tenant (https://aws.amazon.com/blogs/database/multi-tenant-data-isolation-with-postgresql-row-level-security/). | Very high |
| 5 | **Tenant context is set per transaction** with `set_config('app.org_id', $1, true)` inside the same sqlx transaction as the queries. Session-level `SET` is banned, and a lint or test enforces this. | Session `SET`; a role per tenant. | Session settings leak to the next pooled checkout. Transaction-local settings reset at COMMIT (AWS blog above; https://www.bytebase.com/blog/postgres-row-level-security-footguns/). **Spikes 2.2/2.3 (2026-11-17): pass.** `crates/a0-spikes` (sqlx-core + sqlx-postgres 0.9.0) proves the three RLS scenarios including pooled-connection reuse at pool size 1, and a lint fails on session-level `SET app.` or `set_config(..., false)` in non-test code. The policy needs `NULLIF(current_setting('app.org_id', true), '')` because the setting stays `''` after a local `set_config` commits. | High |
| 6 | **Primary keys are UUIDv7 from `uuidv7()`**, and the app may also generate v7 IDs. No serial IDs are exposed. | bigserial (guessable, leaks counts, breaks merges); UUIDv4 (poor index locality). | `uuidv7()` is built into PG 18 (PG 18 release notes, https://www.postgresql.org/about/news/). **Spike 2.1: pass** (`uuidv7()` verified on 18.7). | Very high |
| 7 | **Every encrypted value carries a versioned header:** `magic(2) ‖ format_ver(1) ‖ alg_id(1) ‖ key_id(16) ‖ nonce ‖ ciphertext ‖ tag`. The AEAD binds AAD = `org_id ‖ secret_id ‖ version ‖ purpose`. The DEK wrap uses the same header. [opus] | Raw AEAD output without a header. | Without an algorithm ID and key ID we cannot rotate keys or move to FIPS (aws-lc-rs) without re-encrypting everything blind. Binding AAD stops a ciphertext from being moved between rows or orgs. Proven by KATs and swap tests. **Spike 2.4 (2026-11-17): pass.** KATs, round trip, and proptests that tamper with each AAD and header field each return a named error; `cargo nextest run -p a0-spikes` -> 31 passed; `just leak-scan` clean. | Very high |
| 8 | **AWS DB service: no RDS Proxy at first.** Services use their own sqlx pool. Dev uses **Aurora Serverless v2 with auto-pause (min 0 ACU)**. The prod choice between RDS and Aurora Multi-AZ is made in P1 from load numbers. | RDS Proxy now; DSQL. | RDS Proxy pins sessions on any `SET`/`set_config` and on `LISTEN`, and an attached proxy stops Serverless v2 from auto-pausing (https://docs.aws.amazon.com/AmazonRDS/latest/UserGuide/rds-proxy-pinning.html). Serverless v2 scales to 0 with auto-pause. Resume takes about 15 s, and storage is still billed while paused (https://docs.aws.amazon.com/AmazonRDS/latest/AuroraUserGuide/aurora-serverless-v2-auto-pause.html). Whether a transaction-local `set_config` pins under the proxy is **[verify]**, checked in P1. | Low, as long as decisions 1–2 hold (both run plain PG). |
| 9 | **Regions:** every org row has a `region` from day one. Start with one US region and add an EU cell later. Regions are separate deployments (cells) with no cross-region database. | A global single database. | Data residency requests are standard in B2B security sales. A `region` column costs nothing now, while moving data between regions later is a migration. KMS quota is per region (row 10). | High |
| 10 | **KMS:** one customer-managed key per environment per region wraps the gateway keys. A customer-supplied key is an enterprise option. Gateways cache unwrapped DEKs for a short time to stay within the KMS rate limit. | One key per tenant by default; multi-Region keys. | $1 per key per month, $0.03 per 10k symmetric requests, 100k keys per region quota. The shared crypto request quota is 10k–100k/s depending on region and is counted across all callers (https://aws.amazon.com/kms/pricing/, https://docs.aws.amazon.com/kms/latest/developerguide/requests-per-second.html). Multi-Region keys share key material across regions, which conflicts with the cell model (row 9). Their caveats are **[verify]** in P1. | High |
| 11 | **Audit storage:** the hash chain lives in Postgres (S5). Signed checkpoints are exported to S3 with Object Lock in **compliance mode** for prod and **governance mode** for dev. | Postgres only (an attacker who owns the DB rewrites history); a public log (Rekor). | In compliance mode no one, including root, can delete or shorten retention. Object Lock needs versioning (https://docs.aws.amazon.com/AmazonS3/latest/userguide/object-lock.html). | Medium |
| 12 | **Account layout:** AWS Organizations plus IAM Identity Center now, both free. OUs: Security (Log Archive, Audit), Infrastructure, Workloads (`control-plane-{dev,prod}`, `gateway-{dev,prod}`), Sandbox. Control Tower is optional later, since its cost is mostly AWS Config. | One account for everything. | AWS multi-account whitepaper OU model (https://docs.aws.amazon.com/whitepapers/latest/organizing-your-aws-environment/recommended-ous-and-accounts.html). Control Tower pricing: no charge itself, AWS Config is the main cost (https://aws.amazon.com/controltower/pricing/). Splitting the gateways into their own account enforces the zero-knowledge model (control plane ≠ gateway trust domain). | Very high once live |
| 13 | **Compute: ECS Fargate first**, with Helm kept for self-host. In `dev`, Fargate tasks (ARM, 0.25 vCPU) exist only while a test session runs (row 16). | EKS. | EKS costs $0.10 per cluster-hour (about $73/month) per environment. ECS and Fargate have no control-plane fee (https://aws.amazon.com/eks/pricing/). Containers keep this easy to change. | Low |
| 14 | **Local parity: every AWS service has a local stand-in that speaks the same protocol, behind a trait or a standard interface.** Aurora PG 18 → `postgres:18` (decision 2 keeps Aurora-only features out of the code). KMS → OpenBao transit behind `KeyProvider`. S3 (Object Lock), STS and Cognito API calls → moto server. The OIDC browser flow → Keycloak. Only AWS-only behaviour is tested in `dev`: failover and auto-pause, IAM database auth, KMS key policies, Object Lock compliance mode, the Cognito managed-login page. Each of these gets a named P1 smoke check. | LocalStack; testing directly against AWS. | LocalStack: public repo archived, EULA (docs/research/oss-building-blocks.md). moto mocks cognito-idp including the JWK URIs, but not the browser OIDC flow (https://moto.readthedocs.io/en/latest/docs/services/cognito-idp.html). `cognito-local` has no OAuth2/OIDC endpoints, and LocalStack Cognito is Pro-only (https://docs.sso.earthobservation.vam.wfp.org/architecture/decisions/adrs/0016-cognito-testing-strategy/). | Low if kept from S1; high if AWS calls leak into code untested |
| 15 | **User management: Amazon Cognito user pools (Essentials tier) in our cloud, Keycloak locally, and any OIDC issuer for self-hosters.** Services speak only generic OIDC: JWTs verified against the issuer's JWKS (issuer, audience, expiry), with no Cognito SDK calls on the request path. Passkeys use Cognito's managed login in AWS and Keycloak locally. T1 confirms this with a spike. | Supabase Auth (owner chose AWS, 2026-11-17); a bundled IdP; Cognito SDK calls in the request path. | Cognito user pools are OIDC providers, and tokens are verified with the pool JWKS (https://docs.aws.amazon.com/cognito/latest/developerguide/amazon-cognito-user-pools-using-tokens-verifying-a-jwt.html). | 16 | **`dev` cost model: under $5/month, about $1–2 idle.** There are two OpenTofu stacks. **base** is always on: IAM, budget and SCPs, 1 KMS key, an S3 bucket with a 1-day lifecycle, a separate audit-checkpoint bucket with Object Lock governance mode and 1-day retention (row 11; a lifecycle rule cannot expire locked versions), ECR keeping the last 2 images, and Aurora Serverless v2 at min 0 ACU with auto-pause. **session** runs on demand (`just aws-up` / `just aws-down`, with auto-destroy if left up): Fargate tasks on a public IP restricted to the caller's IP. Check whether the account has free-plan credits **[verify]**. | Low |
| 17 | **Budget guardrails in the management account:** an AWS Budget on the dev account capped at **$5/month**, with email at $1 and $3 and, at $5, a budget action that attaches a deny-create SCP. Standing SCPs on the dev account allow one region only and deny the banned items in row 16, large instance types, Marketplace subscriptions, reserved and Savings Plans purchases, and changes to the guardrails. Cost Anomaly Detection is on. | Alerts only; guardrails inside the dev account. | Budget actions can attach an SCP, but only from the management account (https://docs.aws.amazon.com/awsaccountbilling/latest/aboutv2/budgets-controls.html). First two action-enabled budgets free **[verify]** (third-party: https://oneuptime.com/blog/post/2026-02-12-create-aws-budget-actions-automatic-cost-control/view). | Low |
| 18 | **How Claude reaches AWS: no AWS keys in a Claude session. Writes through MCP are allowed, but each one needs owner approval after a change brief.** The managed **AWS MCP Server** runs on the owner's laptop via Remote Control with IAM Identity Center short-lived credentials. After D2, Locksmith's own STS delegation replaces the laptop path. **Reads** (describe, list, get, logs, `ce:Get*`) run without asking. **Every mutating call** goes through a `PreToolUse` hook that classifies the AWS call by verb and forces an approval prompt, in every permission mode. Before that prompt, Claude posts a **change brief**: what will be created, changed or deleted; estimated monthly cost and the effect on the $5 budget; blast radius (what breaks if it goes wrong); security effect (IAM, network exposure, data); and how to roll back. Everything created through MCP is tagged `created-by=claude-mcp` and, before the session ends, is either imported into OpenTofu or destroyed, so OpenTofu stays the source of truth. The MCP role can never change the guardrails: IAM, Organizations, SCPs, Budgets and the Identity Center configuration are denied when the call comes through MCP (`aws:ViaAWSMCPService`), except `iam:PassRole` limited to the session stack's Fargate task and execution roles, so that MCP can still start the session stack. Those change only through OpenTofu PRs applied by GitHub Actions OIDC. | AWS keys in session env vars; MCP read-only with every change via PR (owner preferred approving each change directly, 2026-11-17); unattended MCP writes. | SigV4 cannot use the session secret proxy (docs/cloud-dev.md). The AWS MCP Server is GA (https://aws.amazon.com/blogs/aws/the-aws-mcp-server-is-now-generally-available) and uses IAM SigV4 (https://docs.aws.amazon.com/agent-toolkit/latest/userguide/getting-started-aws-mcp-server.html). The MCP condition keys and the exact tool names the hook matches are **[verify]** in P1. The tag-and-reconcile rule keeps row 16's "destroy in one command" property. | Low |

## Built in-house
- The 20-odd-byte ciphertext header: no standard envelope format fits gateway wrapping plus AAD binding. Before designing it, `age` and HPKE were considered. `age` remains the format for export files.
- The RLS policies, which are plain SQL.

## How an agent debugs this
- The `postgres` MCP shows policies with `SELECT * FROM pg_policies`, and `just psql` with `SET ROLE app` reproduces a cross-tenant read.
- Spike output: `cargo nextest run -p a0-spikes`.
- Header failures print the field that failed (magic, version, alg, key_id, AAD) and never the plaintext.

Owner answers recorded 2026-11-17: user management on AWS (Cognito), not Supabase. Everything in AWS must be testable locally (row 14). The `dev` budget is $5/month (rows 16–17). Claude may create resources through the AWS MCP, but only with the owner's approval of each change after a change brief (row 18). **First region: us-east-1** (owner, 2026-11-17), so the dev region-lock SCP allows only us-east-1. **EU data residency is not needed at launch.** Per row 9, an EU cell is added when a customer needs it. GDPR still applies to EU users' personal data, such as Cognito emails, wherever it is stored.
