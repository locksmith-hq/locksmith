# Proposal: M12 Auto-Update Delivery System

## Why

Locksmith sits in the path of every credential operation, so the update channel is a top-tier
target. A compromised update would exfiltrate every user's secrets. It is also how security fixes
reach users quickly. M0's minisign self-update is fine for internal testers. Public distribution
needs protection against rollback, freeze and mix-and-match attacks, plus key compromise recovery,
channels, staged rollouts, a kill switch and safe daemon restarts. v5 has none of this.

## What Changes

- **TUF repository** (The Update Framework) generated by CI and served from Cloudflare R2 + CDN at
  `updates.<domain>`. Roles: root (offline, 2-of-3 hardware keys), targets (offline signing
  ceremony per release, or a KMS key with 2-person approval), snapshot and timestamp (online, KMS,
  timestamp expires in 1 day).
- **Channels** as delegated targets: `stable`, `beta`, `nightly`. Enterprise pins rings to a version.
- **Staged rollout:** each target carries `rollout: {percent, started_at}`. A client installs when
  `H(install_id ‖ version) mod 100 < percent`. CI or a release manager raises the percent
  (1 → 10 → 50 → 100) based on health signals.
- **Kill switch / yank:** publishing new targets metadata without a version halts rollout within one
  timestamp period. A `min_secure_version` field marks versions with known vulnerabilities.
- **Client (`ls-update`):** a TUF client (`tough` crate) that checks every 6 h and on `smith` start
  (rate-limited). It downloads to a staging dir, verifies TUF plus the platform code signature
  (codesign/notarization staple on macOS, Authenticode in M16), then installs atomically.
- **Daemon hot-swap:** the daemon drains (no new leases, finishes in-flight ops for up to 30 s,
  notifies active sessions), the binary swaps, the service manager restarts it, and the user
  re-unlocks with one Touch ID. A post-update health check (`smith doctor --quick`) runs, with
  automatic rollback to the kept previous version if it fails within 60 s.
- **Package-manager installs** (Homebrew, apt/rpm repos, WinGet in M16): the updater detects them
  and defers to the package manager. It notifies only.
- **Desktop app:** the Tauri updater plugin consumes a JSON feed generated from the same TUF
  targets, so there is one source of truth.
- **Plugins and extensions:** version compatibility of `integrations/*` is checked by
  `smith doctor`. The VS Code extension uses the Marketplace, and the Claude Code plugin uses its
  marketplace.
- Policy: auto-install for patch versions, ask for minor and major versions (configurable). Updates
  are never forced, except that below `min_secure_version`, *new sessions* show a blocking warning
  that the user can override for 24 h. Unlock and export are never blocked (never-hostage rule).
- Release tooling: `just release <version>` creates the tag. CI builds, signs, notarizes and stages
  into TUF `nightly`/`beta`. `just promote <version> stable --percent 10` advances the rollout.

## Usable outcome

Users get verified updates automatically, in stages. A bad release is stopped within an hour, and a
security fix reaches all online stable users within a day.

### Modified Capabilities
- `update-delivery`: Replaces M0's signed-manifest transport with TUF, and adds channels, staged
  rollout, kill switch, minimum secure version, daemon hot-swap and rollback. Added as new
  requirements because the base spec is archived from M0.

## Out of scope

- Delta or binary-diff updates. Full archives are about 15 MB, which is acceptable.
- Windows installers and Authenticode (M16).

## Impact

`ls-update`, `release.yml`, a `promote.yml` workflow, `infra/` (R2 bucket, CDN, KMS keys), a
documented key ceremony in `docs/security/update-keys.md`.
