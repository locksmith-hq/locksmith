# Design: S6 adversarial gate 1

## Context
- `tests/adversarial/run.sh` already gives the harness: a fresh canary per case, a throwaway `HOME`, an artifact directory, exit 77 for skip, `ADVERSARIAL_REQUIRE_ALL=1` to turn skips into failures, and `--agent claude` for live runs. `tests/kit/oracle.py` (stdlib only, `python3 -I`) is the independent judge; it also backs `just leak-scan` over Postgres, Loki and Tempo.
- The existing cases A0 to A6a attack the local vault and `locksmithd` (v6 inventory). `fixtures/http_upstream.py` (A3b) already reflects a request in many encodings and compressions; S6 reuses it as the bound provider and as the attacker's host.
- The gateway (`services/gateway/src/relay.rs`) asks for identity encoding only, refuses `Content-Encoding` it cannot scan, redacts with `ls-redact` (plain, base64 at three offsets, URL, hex, JSON), re-checks, refuses secrets shorter than 8 bytes (`MIN_ENCODED_LEN`), does not follow redirects and decrypts only for a bound host. Its in-crate test harness has a fake KMS, a fake material source and wiremock upstreams (`echoed_secret_is_redacted_in_every_encoding`, `redirect_is_not_followed`, `logs_hold_no_secret`).
- S5 (in review) adds the ledger with `attempt`, `outcome` and `denied` events, `GET /v1/audit/events`, and a JSON Lines export directory.
- Repo CI policy (AGENTS.md, `docs/cloud-dev.md`): GitHub Actions runs only lint, format and seconds-long hygiene. Tests, Docker and e2e run in the agent VM through `just ci` and the change's Local verification. The weekly `adversarial.yml` is a pre-existing exception that runs only offline `run.sh all`. Agents may not edit `.github/workflows` or `docs/agents` (`scripts/check-task-edits.sh`).
- Binding decisions: A0-4 and A0-5 (tenant isolation the G5 cross-org probes rely on), A0-11 (ledger), A0-15 (JWKS-verified tokens, G6).

## Goals / Non-Goals
**Goals:** a repeatable gate that tries the extraction routes an agent actually has (environment, reflection, header echo, encodings, API surfaces, token replay) against S1 to S5; an independent judge; an honest list of what still leaks and why; a fast tier in every `just ci` and a stack tier in every change's Local verification and nightly.
**Non-Goals:** proving the gateway cannot leak (redaction is detection of known forms, S3 decision 9); host compromise, memory and side channels; a GitHub Actions job.

Built in-house: the G cases, the residual register logic in `run.sh`, and the new oracle forms. Searched first: promptfoo, garak and PyRIT (model-output red teaming, no notion of a credential that must not come back through a tool), gitleaks and betterleaks (pattern scanners for known credential formats), and the A3b fixture (reused as is). The harness and oracle are ours already (F1). `ls-redact` is Apache-2.0 SDK-side code and adds only a permissive crate already in the lockfile.

## Risks / Trade-offs
- [Oracle false positives from new forms, e.g. short base32 or UTF-16 runs in binary logs] → forms are built from the full 32-byte canary (43+ characters), so a chance match is negligible; the self-test includes a clean-corpus check.
- [Redactor cost from more forms] → each form is one more Aho-Corasick pattern per secret; the fast tier records relay latency before and after in progress.md.
- [Residual register used to wave leaks through] → each entry needs a label and reason, stale entries fail the run, and the merge review reads every added line.
- [Live runs are nondeterministic and cost tokens] → live mode only in the stack tier and nightly; fixed prompts; a skip is a failure only where `ADVERSARIAL_REQUIRE_ALL=1`.
- [Nightly depends on an owner action] → until the routine exists, the stack tier still runs in every change's Local verification; the open question below tracks it.

## How an agent debugs this
- `just up`, `just api`, then `just adversarial-gate` (or `bash tests/adversarial/run.sh gateway G3` for one case; `--agent claude` for live). Each case's log and artifact directory are kept under the run's temp directory when `ADVERSARIAL_KEEP=1`.
- `python3 -I tests/kit/oracle.py scan --canary-file <f> <artifact dir>` reproduces a hit and prints `LEAK <encoding> <file>:<offset>`, never the value.
- Fast tier: `cargo nextest run -p ls-gateway adversarial`.
- Postgres MCP: `select seq, kind, outcome, attrs from audit_events order by at desc limit 50` to see the `denied` and `redaction_failed` events each case caused.
- Grafana/Tempo spans `relay`, `verify_token`, `audit.append` (attributes: agent id, outcome; never values). Loki: `{service="gateway"} |= "redaction_failed"`.
- `just leak-scan` (Postgres, Loki, Tempo) and `just audit-verify` after a run.

## Open Questions
- Owner: create the nightly routine (decision 8) and decide whether it posts to `agent-log` or opens a `needs-owner` issue on failure.
- Owner: whether the cloud VM has an `ANTHROPIC_API_KEY` for live mode; without it the nightly run fails with `skip live` by design.
- Whether HTML entities and quoted-printable should move from the residual register into `ls-redact` after the first nightly results show how often real upstreams use them.
